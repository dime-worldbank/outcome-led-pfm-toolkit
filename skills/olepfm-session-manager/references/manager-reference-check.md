# Reference Check Tables

**What this is.** A table appended to every drafted output that cites a source, and merged into one per chapter at compilation. Each row tests two things about one claim: whether the platform can **reach the text content** of the document the claim rests on, by opening it in this session, and whether that text **supports the claim** as written, shown by the exact passage. A link, a title in an index or an entry in another document's bibliography proves neither. A source whose text cannot be reached is shown as not reachable, and a claim whose passage cannot be found is shown as not verified, rather than hidden.

**When to produce it.** Every time a prompt's output cites a source, in the same output: a drafted section, a populated annex table, a chart with its data table, a Working Table in workshop mode, or a redraft at a ✏️ point. Append the table after that output under the heading **Reference check: [section or table]**, and add the item *Reference check table reviewed; every not-reachable, not-verified, partially supported or uncited row resolved* to that prompt's ✏️ checklist. An output that cites nothing says so in one line instead of a table. At each step's compilation prompt, Prompt 1-15 (Chapters 1 and 2), 2-10 (Chapter 3) and 3-14 (Chapters 4 and 5), merge the section tables into one per chapter, after its last section, under the heading **Reference check: Chapter [n]**, re-checking any claim the compilation changed. If the user revises a chapter afterwards, update its table with it. Annex tables carry their own source rows and citations and still get a reference check table when first populated. Workshop mode (`manager-workshop.md`) applies the rule to each populated Working Table (1.1 to 2.1). The Joint Action Plan skill applies it to each drafted section of the plan, with the sector reports and supplementary sources as the documents.

## The reachability test

A source's text is **reachable** when the environment's retrieval tools return the document's own text in this session and the AI reads the passage from it. Which tools those are depends on where the session runs. On the institutional platform they are exactly two: the internal knowledge base index and the `project_search` vector index; a URL counts for nothing there (see Reachability on the platform in `manager-platform.md`). In Claude Code they are the files the user provided, a URL fetched and read now, and a database value the API or explorer returns now. Test every source by retrieving it at the time of the check, even if it was retrieved earlier in the session or its Status in the running source table says Indexed or Uploaded. Nothing else counts: not a search-result snippet, not the running table's Status or Download link, not a bibliography entry in another document, not a title found in the index whose text the search does not return (a scanned PDF, an image, a corrupted file), not a URL that fails to open, and not memory of the document from training. Metadata is not text.

On the institutional platform, Prompt S-5 (`manager-platform.md`) records where each source is. That Status says where a document sits; this test says that the knowledge base or `project_search` actually returned its text. Both are needed, and the reference check never copies the Status in place of retrieving the text.

## Columns

| Column | What goes in it |
|---|---|
| **Section** | The section number where the claim appears, for example 2.3.2 |
| **Claim in the report** | The sentence or figure as written in the chapter, verbatim and kept short. If one sentence makes two claims from two sources, give each its own row |
| **Source** | The source's number in the running source table and the citation as it appears in the text, for example 7, (MoH, 2023). *Uncited* where the text has no citation |
| **Document URL** | The Download link from the running source table where there is one, otherwise its Link. For a document read from a file rather than a URL, give the file name (on the institutional platform, the name it is stored under) |
| **Text reachable** | The result of the reachability test, with how the text was opened: *Yes: knowledge base (stored as xyz.pdf)*, *Yes: project_search (uploaded as name)*, *Yes: URL opened* (Claude Code only), *Yes: Data360 value returned*; or *No* with the reason: *No: not indexed in the knowledge base or project_search*, *No: indexed but text not returned*, *No: URL did not open*, *No: value not returned*. Never *Yes* on the strength of the running table, a snippet or memory |
| **Exact text from the document** | Only when Text reachable is *Yes*: the shortest verbatim passage that supports the claim, in quotation marks, usually one or two sentences, with the page, table or figure number where the document has one. For a data point from a database, the indicator name, value and year as displayed. If the document is not in English, quote the original and add an English translation in brackets. When Text reachable is *No*, write **Not reachable** and nothing else. When it is *Yes* but no passage supports the claim, write **Not verified: passage not found** |

## Rules for the quotations

1. **Verbatim only.** Copy the passage exactly as it appears in the document, with its figures and units. Never paraphrase, reconstruct, tidy or shorten a quotation in your own words. Use an ellipsis (…) only to drop words from the middle of one passage, never to join sentences from different places.
2. **Never invent a passage.** Quote only from text you opened in this check. If the text could not be reached, the row says **Not reachable**; if the passage is not there, **Not verified: passage not found**, without quotation marks. An unreachable or unverified row is useful to the user; an invented quotation is worse than no citation.
3. **The passage must support the claim as written.** If it supports only part of the claim, or a weaker version of it, quote it and add *(supports partially: …)* with a few words on what the document does not say, so the user can decide whether to soften the claim.
4. **One row per claim.** Every parenthetical citation in the chapter has a row. So does every number, date, named law, programme or policy, and every statement about performance that has no citation; its Source column reads *Uncited*, and the user decides whether to add a source or qualify the claim.
5. **Chart and table data.** Every number shown in a chart or in a chart's underlying data table has a reference-check row in the chapter where the chart appears, one row per data-point family (for example, per series or per year block), consistent with rule 4's requirement that every number gets a row. For a value taken from Data360 (or another structured database):
   - **Source column**: the running-table source number and the in-text citation, plus the indicator name, value and year as displayed and the indicator code (for example, *Government expenditure on education, total (% of government expenditure)*, WDI, `WB_WDI_SE_XPD_TOTL_GB_ZS`, 2024).
   - **Document URL column**: the Data360 source link: the explorer link (`https://data360.worldbank.org`) where the site is reachable, otherwise the Data360 API query URL, or the indicator code if neither is available.
   - **Text reachable column**: *Yes: Data360 value returned* only when the API or explorer returned the value in this session; otherwise *No: value not returned*.
   - **Exact text column**: the indicator name, value and year exactly as returned by the source. Because Data360 values carry verifiable claim tags, these rows are treated as **verified**, not "not verified", provided the value in the table matches the value returned by the source.
   A chart value whose figure cannot be matched to a returned source value is marked **Not verified: passage not found**, exactly as for prose claims.

## After each table

Below the table give a one-line tally: rows in total, reachable, not reachable, verified, partially supported, not verified, uncited. The user reviews each table at its prompt's ✏️ point and the merged tables again before the step's completion gate, which asks for it. Resolve every row that is not reachable, not verified, partially supported or uncited before the draft is confirmed. For a not-reachable source, ask the user to upload the document or a saved copy of the page, or re-source the claim to a document whose text can be reached; otherwise find the passage, soften the claim or remove it. Nothing unresolved carries into the next prompt or into compilation.

## In Compilation and QA

The tables are review aids, not part of the report. Leave them out of the compiled chapters and documents (Prompts C-02 to C-13) unless the user asks to keep them, for example as a reviewers' annex. The consistency audit (Prompt C-01, item (vi) on citations) can start from the tallies: any row still not reachable, not verified or partially supported is a citation to settle before compilation.

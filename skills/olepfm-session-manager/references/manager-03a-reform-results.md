## Sub-step 3.1 — Explore the causes of priority bottlenecks (Annex Table 3.1)

Annex Table 3.1 is the analytical foundation for Chapter 4. It must be prepared and confirmed before drafting Section 4.1. Run Prompt 3-02 once for each priority bottleneck, then compile with Prompt 3-03, before beginning the Section 4.1 prompts.

### ✏️ Review the output — focus on these points

**Annex Table 3.1 entry, per bottleneck (Prompt 3-02).** Check each entry after it's produced, before the next bottleneck. A reform can only be as complete as the cause analysis behind it, and Table 3.1 is where causes convert into reforms, so the five-whys must be at its most exhaustive here.

- [ ] A multi-branch five-whys was run for each sub-bottleneck — multiple first-level branches, each followed to its evidentiary end (working analysis shown)
- [ ] The raw cause list is genuinely exhaustive (typically 10–20+ per sub-bottleneck); a short list signals collapsed branches — send it back
- [ ] The Underlying Causes column distils the raw list into 4–7 concrete root-cause families, each carrying its raw-cause codes and citations — not generic statements such as "weak institutions" or "limited capacity"
- [ ] Every root-cause family is addressed by at least one reform, and every reform traces to a cause family (coverage check)
- [ ] Any cause family out of scope for PFM reform is flagged as a parallel track, not silently dropped
- [ ] The taxonomy classification references the correct OLePFM Synthesis Annex 4 category (check the category number and label against the Synthesis Handbook)
- [ ] All key stakeholders are named at the organizational level — not just "government" or "development partners" — including any actor whose resistance could block the reform
- [ ] Every reform result is written as a concrete, measurable end-state (not a process or activity), with a feasibility rating consistent with Annex Tables 2.2 and 2.3
- [ ] The level of detail lets Table 3.1 stand alone as a self-explanatory reference, without the chapter narrative

**Make corrections before proceeding to the next bottleneck.**

### Prompt 3-02 — Annex Table 3.1 Entry per Bottleneck, with Multi-Branch Cause Derivation (repeat for each bottleneck)

Please prepare the Annex Step 3 Table 3.1 entry for Priority Bottleneck [number]: [paste bottleneck title from Section 3.2.2], for [country] in the [sector] sector.

**(a) Multi-branch five-whys per sub-bottleneck (working analysis).** Before completing the table columns, for each sub-bottleneck of this priority bottleneck, derive its underlying causes using a multi-branch five-whys interrogation:

- Ask "why does this sub-bottleneck exist?" and list all distinct first-level answers (aim for 3–6); treat each as the head of its own branch.
- Follow every branch to its evidentiary end — keep asking "why?" (typically three to five levels) until a root cause is reached for which there is no further supporting evidence, or the cause becomes exogenous/structural. Split any multi-cause answer into sub-branches and follow each.
- Tag every discrete cause with a running code [c1], [c2], [c3], … and attach a hyperlinked citation or PEFA indicator wherever the cause is evidenced; mark unevidenced strands "(no further evidence)".
- A thorough interrogation of a significant sub-bottleneck typically yields 10–20+ discrete causes across its branches; if you have markedly fewer, you have very likely collapsed branches — re-open them.
- Present this working five-whys (branches + coded raw list) beneath the table entry as a collapsible/working annex, so the audit trail from cause to reform is visible.

**(b) Distil the Underlying Causes column from the raw list.** Group the coded raw causes into the distinct root-cause families for the sub-bottleneck (typically four to seven families, more where the interrogation warrants it). Each family named in the Underlying Causes column must:

- name a concrete institutional, regulatory, technical, PFM, or political-economy failure (never a generic "weak institutions"/"limited capacity");
- cite sources as hyperlinked parentheticals where available;
- carry the raw-cause codes it consolidates (e.g. [c3, c7, c11]), so each reform can be traced back to the causes it addresses.

**(c) Ensure reform coverage.** Every root-cause family must be addressed by at least one entry in the Reforms Required column; conversely, every reform must trace to a cause family. Explicitly flag any cause family that is out of scope for a PFM reform programme (parallel track) rather than silently dropping it.

Then produce the table entry in the format of the OLePFM Sector Reform Design Report Template:

A header row in the template's form — **Bottleneck [number]: [title]** in the first column and **Change Objective [number]: [change objective, as stated in Section 3.2.2]** in the second — also listing the OLePFM Synthesis Annex 4 taxonomy categories that apply to this bottleneck as a whole (e.g. Category 6: Inefficient deployment and management of resources; Category 3: Unsustainable fiscal position).

One substantive row per sub-bottleneck, with the following columns:

| Column | Content required |
|---|---|
| Sub-Bottlenecks (problems) | A clear title and a description (approximately 80 words) of the specific nature and extent of the sub-bottleneck, the gap it creates in the system, and the OLePFM taxonomy sub-category code that applies (e.g. Taxonomy: 6.1; 7.2). |
| Underlying Causes | The root-cause families distilled from the multi-branch five-whys in (a) — typically four to seven, each a concrete failure with hyperlinked citations, e.g. ([World Bank, 2010](https://…)), and the raw-cause codes it consolidates (e.g. [c2, c5]). No generic causes; no branch left un-interrogated. |
| Stakeholders | All key organizations — by specific name, not type — whose behaviour or decisions must change for this reform result to be achieved. Include: the organization(s) with formal authority over the change; those who must implement it; those whose compliance is required; and any actor whose resistance could block it. |
| Reform Result (Resolved Problem) | The reform result(s) that resolve this sub-bottleneck, written as a concrete measurable end-state in approximately 80–100 words. Label each result as Reform Result [number.sub-number] and end with Feasibility: [H/M/L]. |
| Reforms Required (which address causes) | The specific reforms which address the underlying causes and deliver the reform result. Each reform should reference the cause family/codes it addresses, and every cause family must be covered by a reform (or flagged as a parallel track). This is the fifth column of Annex Table 3.1 in the template. |
